# TDD (Test-Driven Development) 효율적 구현 프롬프트

AI 어시스턴트님, 앞으로 코드를 작성하거나 수정할 때 **반드시 TDD(Test-Driven Development) 방법론**을 엄격하게 준수하여 진행해 주세요. 아래의 규칙과 절차를 기반으로 작업해야 합니다.

## 1. 핵심 프로세스: Red - Green - Refactor
모든 기능 개발은 다음 3단계 사이클을 반복하여 진행해 주세요.

*   **Red (테스트 작성):** 실제 구현 코드를 작성하기 전에, 요구사항을 검증하는 실패하는 테스트 코드(Unit, Integration, E2E)를 먼저 작성하세요. 테스트가 실패하는 것을 확인해야 합니다.
*   **Green (기능 구현):** 방금 작성한 실패하는 테스트를 통과시킬 수 있는 최소한의 실제 코드를 작성하세요. 가장 빠르고 단순한 방법으로 테스트를 통과시키는 데 집중하세요.
*   **Refactor (리팩토링):** 테스트가 통과했다면, 코드의 중복을 제거하고 클린 아키텍처 원칙에 맞게 설계 및 구조를 개선하세요. 리팩토링 후에도 모든 테스트는 여전히 통과해야 합니다.

## 2. 테스트 커버리지 및 종류
*   **커버리지 (Coverage):** 전체 코드의 테스트 커버리지는 항상 **80% 이상**을 유지하도록 테스트를 작성해 주세요.
*   **테스트 레벨:** 다음 세 가지 레벨의 테스트를 모두 작성해야 합니다.
    *   **Unit Test (단위 테스트):** 개별 함수, 클래스, 컴포넌트 등 가장 작은 단위의 로직을 독립적으로 검증하세요. (예: Jest, React Testing Library 등 활용)
    *   **Integration Test (통합 테스트):** 여러 모듈이나 컴포넌트가 함께 상호작용할 때 예상대로 동작하는지 검증하세요. (예: DB 연동 로직과 비즈니스 로직의 통합)
    *   **E2E Test (단대단 테스트):** 사용자의 실제 사용 흐름(시나리오)을 처음부터 끝까지 시뮬레이션하여 검증하세요. (예: Cypress, Playwright 등 활용)

## 3. 테스트 실행 및 디버깅 절차
*   **전체 테스트 확인:** 모든 구현(Green/Refactor) 단계가 끝난 후에는 반드시 전체 테스트 스위트를 다시 실행하여 **모든 테스트가 통과하는지 최종 확인**해 주세요.
*   **실패 원인 분석 및 수정:** 만약 단 하나의 테스트라도 통과하지 못한다면, 다음 절차를 따르세요.
    1.  어떤 테스트가 왜 통과하지 못했는지 오류 메시지와 함께 **자세히 원인을 분석**하여 설명해 주세요.
    2.  분석 결과를 바탕으로 코드를 수정하고, 다시 테스트를 실행하여 통과 여부를 확인하세요.
    3.  모든 테스트가 'Green' 상태가 될 때까지 이 과정을 반복하세요.

## 4. 진행 방식 요약
1. 목표 기능 설명
2. [Red] 테스트 코드(Unit, Integration, E2E) 작성 및 실패 확인
3. [Green] 기능 구현 및 테스트 통과 확인
4. [Refactor] 코드 정리
5. [Final Check] 전체 테스트 실행 및 커버리지(80% 이상) 확인
6. (실패 시) 상세 원인 분석 및 코드 수정
